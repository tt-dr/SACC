# 南邮计软院科协官网建设项目书

## Summer of Code 2025 — 技术部前端组

---

## 一、项目概述

### 1.1 项目名称

**南邮科协官网（SACC Website）V1.0 前端开发**

### 1.2 项目背景

南京邮电大学计算机学院、软件学院、网络空间安全学院科学技术协会（SACC）目前尚无独立官方网站，对外宣传、活动发布、成果展示、招新报名等均依赖零散的第三方平台，缺乏统一的品牌形象与信息集散入口。

作为技术部前端组组长，我计划借本次 Summer of Code 活动，带领组员**从零搭建**科协官网前端，覆盖需求分析、技术选型、架构设计、UI 开发全流程，打造一套现代化、高性能、可维护的科协官方站点。

### 1.3 项目目标

- **品牌建立**：打造统一的科协视觉形象与线上门户，承载部门介绍、活动发布、竞赛成果、招新入口
- **全端适配**：完美兼容 PC / 平板 / 移动端，响应式与自适应结合
- **高性能**：Lighthouse 评分 ≥ 90，首屏加载时间 < 2s
- **内容可维护**：基于 MDX 文件驱动，内容即代码，无需数据库，部员即可通过 PR 更新内容
- **组件化沉淀**：积累一套可复用的 UI 组件，供科协后续活动页面直接使用
- **工程化闭环**：建立代码规范、分支策略、CI/CD 自动化部署流程
- **管理后台前端**：内容管理端的前端界面，通过约定接口与后端读写数据

### 1.4 职责边界（前端组）

本项目由**技术部前端组**负责，职责聚焦于**前端开发**：页面与组件实现、Markdown/MDX 内容解析与渲染、响应式与无障碍、前端工程化与部署。

数据持久化、后端接口、数据库与服务端部署由**后端组**另行负责。官网前台以静态内容为主（**加入我们为招新公告，无需提交表单**）；内容管理后台前端通过**约定接口**与后端读写数据，前端不承担后端实现工作。

### 1.5 设计参考

设计稿由 `UI/` 目录提供，包括 `SACC.pen` 设计源文件、`api-doc.json` 接口文档以及两个 React 原型项目预览。设计稿**仅在浏览器中打开用于 UI 参考**，不直接复用其代码，最终项目从零搭建，不包含 UI 设计稿文件。

## 二、技术方案

### 2.1 技术选型

| 层级 | 技术 | 选型理由 |
|------|------|----------|
| 核心框架 | **React 19** + **TypeScript** | 团队主力技术栈，学习成本可控；类型安全利于长期维护 |
| 元框架 | **Next.js 15 (App Router)** | SSR/SSG/ISR 三合一，SEO 友好；Server Components 极致性能 |
| 样式方案 | **Tailwind CSS 4** | 原子化 CSS，开发效率高；设计约束内建于 class 命名 |
| 组件体系 | **shadcn/ui** + **Radix Primitives** | 无头组件库，可访问性内置，复制即拥有，零运行时依赖膨胀 |
| 动效 | **CSS Transition/Animation** 为主，**Framer Motion** 补充 | 优先原生方案减少 JS 体积；复杂编排场景才引入 Framer |
| 内容层 | **MDX (next-mdx-remote)** | 文章/公告以 `.mdx` 文件存储于仓库，前端解析渲染，零成本零运维，支持版本管理 |
| 包管理 | **pnpm** | 磁盘高效，严格依赖解析 |
| 代码规范 | **ESLint Flat Config** + **Prettier** + **commitlint** | 统一编码风格与提交规范 |
| 测试 | **Vitest** + **React Testing Library** | 核心组件单元测试；E2E 以手动回归 Checklist 补充 |
| CI/CD | **GitHub Actions** + **Vercel** | PR 预览 + 合入主干自动部署 |

### 2.3 站点信息架构与核心功能

#### 顶部导航

官网顶部栏固定保留七个主入口：

| 导航 | 路由 | 说明 |
|------|------|------|
| **主页** | `/` | 品牌 Hero、社团亮点、精选文档与成员动态入口 |
| **关于我们** | `/about` | 使命愿景、能力矩阵、发展历程与荣誉 |
| **文档库** | `/docs` | 项目文档中心，左侧分类列表 + 右侧自动目录 |
| **成员动态** | `/news` | 成员博客，支持作者筛选、搜索与时间排序 |
| **项目** | `/projects` | GitHub 项目展示，卡片直达代码仓库 |
| **活动** | `/activities` | 科协活动列表与详情 |
| **团队** | `/team` | 团队架构展示（主席团 / 技术部门 / 非技术部门） |
| **加入我们** | `/join` | 招新公告：社群二维码 + 群号 + 加入指引（无表单提交） |

#### 关键页面

- **首页（Home）**：品牌 Hero（Logo 动画 + 光泽粒子效果）、核心统计数据（总访问量、活跃成员等）、精选活动卡片、最新成员动态列表、合作伙伴与资源入口、加入我们 CTA。

- **关于我们（About）**：使命与愿景卡片、部门能力矩阵、历年荣誉展示、核心价值观、技术发展历程时间轴。

- **文档库（Docs）**：三栏式文档中心。左侧栏按分类列出全部文档并高亮当前项，中间区域渲染 Markdown 正文，右侧栏基于正文标题自动生成本文目录（TOC），点击锚点定位到对应小节。

- **成员动态（News）**：聚合成员发布的技术博客。默认按发布时间倒序（新内容在前），支持按作者一键筛选与关键词搜索（标题 / 摘要 / 标签），命中为空时给出空状态提示；点击卡片进入博客详情页，详情页含作者侧栏（同一作者其他文章）、文章元数据与标签、正文 TOC。

- **项目展示（Projects）**：以卡片形式展示 GitHub 项目（摘要、状态、进度、负责人、技术栈）。**不设二级详情页**，每张卡片仅提供一个「进入项目仓库」的外链，直接跳转到对应的 GitHub 仓库。

- **活动（Activities）**：活动列表卡片展示类别、名额、日期、地点等基本信息；点击进入活动详情页，查看活动议程、成果展示。

- **团队架构（Team）**：Tab 切换展示科协成员架构（主席团 / 技术部门 / 非技术部门 / 团队介绍），以头像卡片形式展示每位成员信息。

- **相册（Gallery）**：精选影集展示页 + 按年份归档浏览。相册封面卡片以特色配色展示。

- **加入我们（Join）**：招新**公告页**，展示加入流程（申请 → 笔试 → 面试）、成长路径、活动福利、QQ 社群二维码与群号。**不做表单提交、无后端交互**。

- **常见问题（FAQ）**：问答卡片形式展示常见问题与解答。

- **404 页面**：提供「返回首页」与「查看项目」操作入口，友好引导。

#### 管理后台功能（前端界面，对接后端接口）

| 模块 | 功能 | 对应约定接口 |
|------|------|-------------|
| **登录鉴权** | 账号密码登录 + 图形验证码，JWT Token 存储与携带 | `POST /api/v1/auth/login` |
| **仪表盘** | 站点统计数据面板、流量趋势图、最近操作审计日志、快捷操作入口 | `GET /api/v1/admin/dashboard` |
| **成员动态管理** | 新建/编辑/删除博客；标题/作者/摘要/标签/正文（Markdown 编辑）；状态管理（草稿/已发布/待审核）；搜索与作者筛选 | `GET/POST/PUT/DELETE /api/v1/admin/content` |
| **文档库管理** | 新建/编辑/删除文档；标题/分类/正文（Markdown 编辑）；拖拽排序文档展示顺序 | `GET/POST/PUT/DELETE /api/v1/admin/content` |
| **项目展示管理** | 新建/编辑/下线项目；名称/仓库链接/标签/摘要/详情；拖拽排序展示顺序 | `GET/POST/PUT/DELETE /api/v1/admin/content` |
| **用户管理** | 仅超级管理员可见；用户列表、创建/编辑账号（用户名/角色/密码）、禁用用户 | `GET/POST/PUT/DELETE /api/v1/admin/users` |
| **个人设置** | 修改密码（需验证旧密码）、上传头像 | `PUT /api/v1/admin/password`、`POST /api/v1/admin/upload` |
| **权限分级** | RBAC 两角色：`super_admin`（全部权限含用户管理）与 `editor`（仅内容管理不含用户管理） | 后端根据 JWT role 字段控制 |

> 说明：管理后台前端界面通过约定接口与后端通信，具体接口定义参见 `api-doc.json`（OpenAPI 3.0 规范）。前端只负责界面实现与接口调用，数据持久化与业务逻辑由后端组负责。

### 2.4 数据流方案

```
┌──────────────┐     ┌───────────────┐     ┌─────────────┐
│ Markdown/MDX │────▶│ 前端解析渲染   │────▶│ 静态页面     │
│ (content/)   │     │ (markdown.ts) │     │ (SSG/ISR)   │
└──────────────┘     └───────────────┘     └─────────────┘

┌──────────────┐     ┌───────────────┐     ┌─────────────┐
│ 管理后台前端 │◀───▶│  约定接口      │◀───▶│ 后端服务     │
│ (admin)      │     │ (前端调用)     │     │ (后端组提供) │
└──────────────┘     └───────────────┘     └─────────────┘
```

> 说明：官网前台内容以 Markdown / 结构化数据驱动，由**前端**解析渲染并通过 SSG/ISR 生成静态页面。加入我们为招新公告（社群二维码 + 群号），项目直链 GitHub，活动/团队/相册/FAQ 为静态内容。**前台不含任何表单提交与后端交互**。仅内容管理后台前端通过约定接口与后端读写数据，数据持久化与存储属于后端职责，不在前端组范围内。

### 2.5 Git 协作规范

| 约定 | 说明 |
|------|------|
| 分支策略 | **Trunk-based**：`main` 保护分支 + `feature/<name>` 短分支 |
| 提交规范 | `feat:` / `fix:` / `docs:` / `chore:` / `refactor:` 前缀 |
| PR 流程 | feature → PR → 组长 Review → Squash Merge → 自动部署 Preview → 合入 main |
| 环境 | `main` 自动部署生产；PR 分支自动部署 Vercel Preview URL |

| MDX 富文本能力有限 | 复杂页面受阻 | 自定义 MDX 组件（Callout、Embed 等），超出能力的内容用 React 页面补充 |
| 后端接口未就绪，管理后台无法联调 | 管理后台进度受阻 | 前端先以 Mock 数据 + localStorage 原型模式开发界面，接口就绪后切换 |
| Vercel 免费额度不够 | 生产不可用 | 备选 Cloudflare Pages 静态托管（免费额度更大） |
| 域名获取周期长 | 上线延迟 | 先用 Vercel 默认 `*.vercel.app` 域名上线，再逐步替换 |
